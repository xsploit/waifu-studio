# Feature status: native companion and WebWaifu4 port

This is a substantial native foundation, **not a complete WebWaifu4 port or full implementation of every researched idea**. Status below reflects inspected source on 2026-10-18. “Implemented” means a code path and controls exist; it does not mean a live provider, microphone, headset, coding agent or every avatar has passed acceptance.

| Requested capability | Implementation status | Scope and acceptance boundary |
| --- | --- | --- |
| Native desktop companion | Implemented | Rust/Bevy, local settings/library and native panels; no browser runtime required. Linux baseline rendered previously; other operating systems remain unverified. |
| VRM 0.x / 1.0 and GLB/glTF avatars | Implemented | Import, switch and unload; failed replacements retain the visible avatar. Existing GPU evidence covers named fixtures, not arbitrary rigs. |
| Bundled characters | Implemented | 22 distinct local VRMs, 3 exact recovered personalities, saved Hikari Fish reference and editable first-run defaults. Existing edits/deletions persist; Piper voice bindings are recorded but Piper inference is not implemented. |
| Per-character customization | Scoped/partial | Name, persona, greeting, chat connection, scene, voice, facial controls and separate mesh-part visibility persist. Search/reset and stable reload keys are implemented. No general mesh/body/outfit editor or character-package exporter. |
| MToon, PBR/unlit, outlines and springs | Implemented | Three appearances and vendored VRM spring/outline support. Original/Soft anime/Crisp cel looks use reversible MToon tuning on avatar-private material variants (imported source assets stay unchanged), with authored matcap, normal-map and emission strength controls; the cel look has a native offscreen Neuro capture. Referenced VRM0 spheres and VRM1 sphere/capsule colliders now drive hair/skirt/accessory endpoints with joint hit radii; not cloth, mesh or self-collision. Visual acceptance pending. |
| Camera, placement, lighting and performance settings | Implemented | Orbit/pan/zoom/reframe, placement/scale, key light, size and FPS caps. Optional WebWaifu4-style linear RGB power/gain correction runs before tonemapping, defaults off, preserves alpha and is suspended in transparent desktop mode; tested with an offscreen Neuro GPU capture. Caps are settings, not measured performance guarantees. |
| Transparent desktop overlay | Scoped/partial | Transparent rendering, compact desktop window, recovery controls, mesh-based native dragging, right-click radial actions, and bundled idle/grabbed/sitting VRMA motions. Standing releases a detected seat and repositions the projected feet onto its edge; offline regression coverage only. Experimental window tracking uses the KDE Wayland bridge or an explicitly enabled Hyprland socket backend to detect windows and reserved taskbar work areas. Hyprland keeps geometry polling off the render thread and requires a floating companion for moves; its stacking order is approximate. Offline fixtures only; live compositor acceptance remains unverified. No collision physics. |
| Native postprocessing | Implemented | Persisted tone-mapping, exposure, saturation/contrast/gamma, bloom and chromatic-aberration controls with presets. Effects are suppressed in transparent desktop mode. Functional equivalents/extensions, not WebWaifu RGB-shader pixel parity. |
| Illustrated/image backgrounds | Implemented | Image/color backgrounds plus three bundled illustrated themes. These are 2D backgrounds. |
| 3D environments | Scoped/partial | Three original procedural scenes plus furnished Rose bedroom, Violet gaming studio and Cyan gaming lounge, wide-room framing, generated wall-art texture and per-character persistence. No navigation or world interaction. |
| BVH, VRMA and FBX motion | Scoped/partial | All three import paths now exist, with play/pause/stop/scrub/loop/speed/weight. The library dropdown filters by filename-derived category as well as folder/search. An explicit Jev suggestion can choose one of up to 16 scanned motions; the user reviews and presses Play. Optional per-reply Suggest or Auto-play modes are persisted and default to Off, with a 10–600 second cooldown, stale-result checks and manual override. An additional off-default emotion-mapped mode rotates through user-selected, currently scanned non-locomotion playlists using metadata from that same completed reply; it makes no extra decision request. Multi-select dropdowns retain missing bindings for removal, single bindings remain compatible, and runtime rotation resets for character/avatar changes. These paths have offline tests; live decision-provider and visual acceptance remain open. Rest-normalized joint rotations, model-height-scaled hips translation converted through source/target armature rest frames, facing correction and 0.5-second clip crossfades. Bundled VRMA poses and two recovered WebWaifu4 Wave FBX samples rendered offscreen on Neuro. No general locomotion controller, constraints or animation graph; arbitrary rigs and live desktop interaction still need acceptance. |
| Facial expressions and blinking | Implemented | Material-only expressions now feed the same facial weights: VRM1 color/emission/shade/matcap/rim/outline and VRM0 common color properties apply additive authored deltas to avatar-private material variants, restore at zero/switch/removal and compose with tuning. Unrotated shared UV0 transforms work in Toon/Lit/Unlit; VRM0 _MainTex_ST expressions convert Unity offsets into glTF UV coordinates; rotated/UV1 expression transforms remain unsupported with status diagnostics. Fixture/schedule tests only; visual acceptance on a material-expression avatar remains open. Voice controls offer an explicit local WAV/MP3 preview (32 MiB maximum) through the same metered playback/viseme path without synthesis calls; physical playback acceptance remains open. The Face panel has read-only live speech-envelope and composed mouth-weight diagnostics, scoped to the selected avatar; they do not establish physical synchronization. VRM0 mesh-index and VRM1 node-index morph bindings, manual weights, selection, WW4 cosine blinking with per-character jitter and saved controls. Optional selected-avatar head/neck gaze composes over animation; authored VRM look-at selects bone range maps or expression-driven eyes. A dropdown selects ambient movement or pointer following within the active avatar viewport, with smoothing and ambient fallback outside; desktop pointer targeting can use fresh compositor-bridge coordinates inside the viewport even during click passthrough; VRM1 expression and VRM0 BlendShape look-at now drive lookLeft/Right/Up/Down through morph/material composition, with manual and overrideLookAt priority. VRM0 flattened Hermite curves are evaluated; malformed maps report fallbacks. Authored maps receive a virtual local target angle with strength applied after mapping, not procedural eye-rotation offsets. No world-space target/offsetFromHeadBone or companion-avatar gaze; representative-avatar visual acceptance is still open. Optional focused-reply metadata drives bounded emotions, including fear/disgust with matching custom expression names only, while optional Jev incoming-message appraisal supplies discrete character-reaction emotion/VAD; new face behavior needs visual acceptance. |
| Speech lip-sync | Scoped/partial | Consumed playback samples feed optional native MFCC A/I/U/E/O analysis on a bounded worker, with explicit uLipSync JSON / wLipSync WLIP calibration import and saved controls. No calibration bundled; unavailable/incompatible analysis falls back to RMS. Explicit method selection, recovery messages and reset controls help restore mouth/analysis tuning without discarding the profile. Mid-speech analysis tuning preserves the analyzer window and drains queued PCM without a sleep between each batch. Numerical/fixture evidence does not establish general phoneme recognition, voice-specific accuracy or perceived synchronization. |
| OpenAI-compatible chat and model selection | Implemented | Streamed chat, editable connections, automatically loaded searchable model catalogs/refresh/custom IDs and optional reasoning dropdowns. Once Vercel discovery has populated this session's capability cache, unsupported explicit reasoning efforts are hidden from the choices and rejected at send time without rewriting saved settings; unknown capabilities remain selectable. Vercel/OpenRouter have separate upstream provider order/allowlists and speed/cost routing controls; OpenAI, xAI and compatible local servers share the chat adapter. Non-chat models are filtered from gateway discovery. Vercel streaming and catalog discovery have bounded live checks; other providers are not live-accepted. |
| Multi-character scenes and group chat | Scoped/partial | Up to four visible avatars, persisted companion placements, independent facial caches/blinks and speaker-targeted lips; explicit serial group replies with separate recipient histories/notes and queued speech. Optional Vercel Jev recipient suggestion and local name routing. Independent animation graphs, shared conversational reasoning and autonomous inter-character dialogue are absent; GPU/audio/live-provider acceptance remains open. |
| Local chat history | Implemented | Separate bounded histories per character. Image payloads are not retained in chat history. |
| Image input/vision chat | Scoped/partial | Explicit PNG/JPEG/WebP attachments, bounded background preparation and compatible image-message requests. Requires a capable model; no continuous camera/screen perception. |
| Vercel, Fish hosted/local and compatible TTS | Implemented | Configurable model/reference or voice fields, buffered audio, preview and automatic reading of replies. Focused buffered/HTTP WAV replies now start on sentence groups while text streams; buffered and HTTP WAV deliveries use bounded two-request prefetch with ordered playback. Scene replies emit filtered sentence groups during generation. WebSocket remains the default; focused timestamp SSE also starts on filtered sentence groups while the LLM streams, with sequential requests gated on network completion and playback drain (no SSE prefetch). Vercel uses its native v4 buffered speech protocol; a five-character openai/tts-1 request returned decodable WAV. This does not establish every model/voice or perceived audio quality. Live Fish synthesis was exercised across five hosted models and all five delivery modes; see benchmarks/RESULTS.md. Speaker onset and audible quality remain untested. |
| Progressive HTTP speech | Implemented | Incremental bounded WAV decoding/playback for Fish HTTP delivery. This is separate from WebSocket text/audio streaming. |
| Fish timestamp SSE | Scoped/partial | Timestamp-SSE decoder, incremental WAV transport, timing display and app wiring compile and pass local fixture tests. Word timings are not phonemes and restart for each sentence request. Bounded live Fish SSE latency runs are recorded in benchmarks/RESULTS.md; physical speaker onset, audible quality and synchronization remain unaccepted. |
| Fish WebSocket text-in/audio-out | Scoped/partial | Hosted binary MessagePack sessions stream reply text into progressive WAV playback, with sentence/manual flush, optional word timestamps, cancellation and split-marker task-proposal filtering. Local protocol fixtures and bounded authenticated latency runs pass; perceived audio quality and live caption synchronization remain unaccepted. |
| Fish voice library | Implemented | Read-only My voices loading on opening the library; own/public voice search, filters, pagination and reference selection; offline HTTP fixtures plus an earlier authenticated read-only GET. No voice cloning/deletion. |
| Fish Voice Design | Scoped/partial | Explicit paid candidate generation and playback previews. Does not create, save/export or install a persistent voice model; candidate IDs are not reusable TTS reference IDs. |
| Microphone, VAD and STT | Scoped/partial | Opt-in default-device capture, streaming band-limited 16 kHz conversion, energy or optional Silero ONNX VAD with sustained-onset/hold hysteresis, direct Fish/OpenAI-compatible/OpenRouter/Vercel transcription adapters; transcript enters the composer for review by default. Optional off-default auto-send captures intent at manual recording start and uses the ordinary chat/speech path only for the same selected character with an empty starting/current draft and ready chat/memory; other transcripts stay for review. Silero requires model/runtime files; its ONNX session is reused across recordings with recurrent state reset, and model/runtime path changes evict it. A silence-delay dropdown offers 400/800/1200 ms without changing existing saved values. An off-default trim option removes VAD-detected leading/trailing silence before upload, keeps 200 ms around the confirmed span and preserves internal pauses; inference failure/backlog keeps the complete clip. It does not shorten endpointing delay. No wake word or full-duplex voice conversation; prerecorded live ASR measurements exist, while physical microphone capture and interactive voice acceptance remain untested. |
| Explicit local memory | Implemented | Per-character editable/pinned/deletable notes, opt-in bounded lexical retrieval and local persistence. A local in-memory inspector explains the latest focused-chat recall, scores and budget/limit exclusions; it does not change prompt text. Group chat has its own latest-request inspector with separate bounded per-recipient note/evidence traces; these do not overwrite focused-chat traces. |
| Evidence-backed memory | Scoped/partial | Opt-in per-character JSONL facts/preferences/questions/reflections with evidence/source, corrections, expiry, duplicate rejection and forgetting. Optional user-turn candidates need explicit acceptance before recall. Separate retention opt-in keeps up to 16 pending candidates across restart with 14-day expiry; opting out removes the pending file. Ledger format remains compatible. Bounded keyword recall in focused and scene requests uses distinct content terms, suppresses common English function words and preserves short identifiers/numbers/negation. Latin-script notes use whole words (tea does not match steak); common CJK queries retain substring matching. Pinned notes retain priority; no vector database is required. Explicit per-character note links and off-default one-hop lexical expansion add at most two linked notes after inserted direct matches, with seed IDs in focused/scene traces; note deletion removes incident links. No inferred relationships or recursive graph search. A local inspector explains the latest focused-chat evidence selection and correction/expiry/budget exclusions; group-chat recalls appear in a separate latest-request inspector. Manual structured reflection drafts cite accepted evidence, enter the pending review queue and require acceptance; optional off-default evidence-triggered drafting uses a saved per-character connection, 1–12 new accepted records and a 10–1440 minute attempt cooldown. Starts from a session baseline, never catches up on launch, pauses for pending reflections, and requires review before recall. Generated reflections revalidate structured source IDs/text revisions at acceptance and recall; source correction removes stale pending drafts, and forgetting removes linked generated records/quotes. Older generated reflections with unstructured citations are inspectable but excluded from recall. No automatic promotion or full Grillo port. Failed pending writes retain their snapshot and error across character switches, with explicit retry. |
| Semantic memory | Scoped/partial | Opt-in embedding index/cache over explicit notes; manually query the draft and attach matching context once to the next request without saving it in chat history. Requires an embeddings endpoint. No automatic conversation embedding, model extraction or autonomous memory formation; live endpoint acceptance remains untested. |
| MCP assistant tools | Scoped/partial | Manual Streamable HTTP discovery/review/call, optional result insertion. No stdio/OAuth/subscriptions or model-controlled automatic tool loop; no live-server acceptance claim. |
| Coding-agent providers | Scoped/partial | Installed Codex CLI, Claude Code, Pi and custom executables; Hermes can use Custom. Existing authentication is inherited. No bundled agents or real model-task acceptance claim. |
| SSH coding-agent execution | Scoped/partial | Reviewed remote CLI invocation with quoting, strict host keys and timeout. No live SSH-host acceptance claim. |
| Multi-agent task board | Scoped/partial | Reviewed independent task cards, bounded concurrent runners, cancellation and result staging. No persistent provider sessions, shared conversation runtime or T3 session/steering parity. |
| Companion-driven task loop | Scoped/partial | Explicitly started, sequential loop with fixed scope and task/model-call limits. No unrestricted continuous agent, silent MCP automation or always-running supervisor. |
| Local lifecycle behavior and emotion previews | Scoped/partial | Opt-in per-character Idle/Thinking/Speaking states, optional expression mappings and explicitly triggered emotions with smoothing/decay. Manual expressions and blink/mouth/look controls are protected; stale lifecycle events are rejected. Optional strict reply emotion/VAD metadata now drives supported focused-avatar expressions with decaying session mood; metadata stays out of speech/display/history. Opted-in group recipients also keep isolated session moods and drive their own supported facial/material expressions; hidden metadata is excluded from group speech/display/history. Trailing metadata arrives after prose, so this is not speech-start synchronization. An alternative off-default Jev source appraises the character’s reaction to incoming messages alongside focused/group generation, with fixed VAD categories, 1.5-second freshness/deadline, two global worker slots, strict choices and no retries. Sources are mutually exclusive; settings/turn changes discard late results. Group body motions, slow drives and behavior-to-voice compilation remain absent. |
| Routines, journals and proactive companionship | Scoped/partial | Off-default weekly fictional activity anchors persist with each character’s scene settings. The Scene panel shows current/next activity in the computer’s local timezone on Unix, handles weekly rollover and rejects duplicate/invalid anchors. Activities last until the next anchor. A separate off-default checkbox shares bounded current/next fictional activity data with focused and group replies, immediately before the latest user turn and outside saved history. No attendance/presence inference, extra model calls, catch-up jobs or messages. Custom timezones, durable background jobs, automatic journals and proactive outreach remain absent; evidence-triggered reflection drafts are separately opt-in and always await review. |
| Jev / OpenAI Decisions / Luna adapters | Scoped/partial | Vercel Jev choice adapters support explicit scene-recipient and review-before-play motion suggestions, with offered-ID/schema/freshness validation. Jev also supports optional bounded incoming-message emotion/VAD appraisal; general memory decisions and direct OpenAI Decisions/Luna integrations remain absent; no live decision-provider comparison. |
| Flybrain/connectome embodiment | Not implemented | Research/design only; no fly controller, trained avatar decoder or learning/personality claim. |
| VR/OpenXR and standalone Quest | Not implemented | Deferred until the desktop companion workflow is accepted. |
| Full WebWaifu4/T3 feature parity | Not implemented | Imported model/motion compatibility and selected native equivalents do not establish an exhaustive port. |

Settings occupy an opaque full page beside navigation, with dropdowns for companions, models, voices, animations and section navigation. Character and Scene pages retain a live rendered VRM dock with full-body/upper-body/face framing, rotation and zoom. Actual production UI captures and simulated selection tests are recorded in VALIDATION.md. Imported rest snapshots correct the shared VRMA/FBX arm-pose defect; KWin dock/drop fixes have offline coverage. Dynamic animation quality and live taskbar sitting still require interactive acceptance.

## Evidence boundary

- Existing validation records earlier native GPU/render captures and automated/offline checks. They do not establish GPU acceptance of the newest facial, VRMA/FBX, semantic-memory, task-board, local-behavior, calibrated-vowel or Fish streaming additions.
- A bounded actual Vercel request streamed exact OK, and Fish authenticated read-only voice listing returned HTTP 200. Live Fish/Vercel pipeline timing results are in benchmarks/RESULTS.md; they do not establish speaker/audio-device acceptance, every Fish feature, live embeddings/STT/MCP, real agent tasks or SSH operation.
- No current claim of headset support, universal avatar compatibility, long-duration leak freedom, release performance or fully tested desktop input behavior is made.
- See [README.md](README.md) for operation, [VALIDATION.md](VALIDATION.md) for the current test receipt, and the customization/memory/decision/T3 research documents for proposed work. Research descriptions are not shipped-feature receipts.


### Integration update — 2026-10-18

Buffered and HTTP WAV single-character replies now speak sentence groups during LLM streaming. HTTP supports bounded two-request prefetch with ordered delivery; scene replies also emit filtered speech groups before completion. Timestamp SSE remains unchanged. Offline tests validate these paths, not a new latency result.

Facts memory now rejects conservative filler-only duplicates and prunes expired correction trees on later saves, with an expiry tooltip explaining permanence. Fable's RGB disable, primary-window gaze, and Hyprland transient recovery/focus-sort findings are fixed. 471 tests and warnings-denied clippy pass; runtime/audio acceptance remains open.
