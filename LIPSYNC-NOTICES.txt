Native Rust uLipSync / wLipSync analysis port
============================================
Source references inspected:
  https://github.com/mrxz/wlipsync

The Rust implementation derives the MFCC pipeline, scoring, calibration-file
format and output smoothing from these MIT-licensed implementations. It uses
native f32 math, not wLipSync's bundled approximate pt_math.h implementation.
No upstream voice calibration data, avatar, or audio recording is bundled.

Validation and deliberate differences:
- Embedded golden tests contain 30 reference vectors: five rates, three scoring
  methods and standardization on/off. They were computed using the pinned
  wLipSync C kernels, native libm float functions, round-half-even and f32 PI.
- The native reference fixes a wasm32-specific FFT bit-width calculation and
  the C pre-emphasis loop's one-past-the-end write. Its small driver selects
  all 12 MFCC coefficients directly, following uLipSync LipSyncJob rather than
  src/main.c's phoneme-count-dependent coefficient-copy loop.
- This is kernel-level numerical evidence, not bit-identical Unity Burst or
  unmodified browser/WASM execution, nor a speech-recognition accuracy claim.
- Inputs below the profile target rate and plans producing a non-power-of-two
  decimated window are rejected. For a 16kHz/1024 profile, 22.05kHz input is
  rejected; common 16/24/44.1/48kHz input has reference coverage.
- Profile dimensions, names, finite coefficients, standard deviations, PCM
  bounds, input-window memory and filter-work limits are validated. Degenerate
  spectra are explicitly silent; diagnostic MFCC values remain finite.
- Buffers/tables allocate on analyzer creation only. Audio analysis must run on
  a bounded worker, never in the audio callback. Existing RMS may be used as a
  fallback when no compatible calibration profile is loaded.
