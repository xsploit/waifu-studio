# Tamanitomo features worth bringing into Waifu Studio

Reference inspected: [official site](https://tamanitomo.com/) and public repository at commit [`f536408bec0b99eef8487e55b78ee40e91a22463`](https://github.com/tamanitomo/tamanitomo/tree/f536408bec0b99eef8487e55b78ee40e91a22463). This is a source review, not a live acceptance test. Tamanitomo uses PolyForm Noncommercial 1.0.0. The proposal below describes independently implementable behavior; no restricted implementation was copied into the Rust app.

## What is real in the reference

- **Memory with provenance:** human claims, companion-authored preferences and imagined episodes are separate. Facts carry evidence/source, corrections append, duplicate detection and expiry reduce stale facts. Structured reflection chooses trusted transcript quote IDs; code attaches verbatim quotations. The documentation explicitly says this does not prove every paraphrase correct, and arbitrary callers can supply quotations the low-level writer cannot authenticate. Retrieval is a bounded lexical aid, not guaranteed semantic understanding. [Architecture: memory](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/docs/ARCHITECTURE.md#evidence-backed-memory)
- **Daily life and reflection:** editable daily/weekly routine anchors describe imagined activities, not proof of attendance or real bookings. Separate presence/life records and structured daily/weekly/monthly reflection exist. [Routine data](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/templates/routine.json.tmpl), [reflection implementation](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/scripts/companion_local_reflection.py)
- **Moods and relationships:** recorded experiences, temperament, recovery and explained absences feed contextual state. Quiet hours govern delivery and do not prove the user is asleep. These are authored character dynamics, not measured human psychology. Documentation distinguishes calculation/prompt tests from broader real-model acceptance. [Feelings](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/docs/FEELINGS.md)
- **Outreach boundaries:** a local dispatcher checks expiry, not-before, recipient, permissions, quiet hours and a durable daily allowance. It reserves under a lock, dispatches at most one item per run, and does not automatically retry uncertain sends. High priority/recent recorded activity may bypass quiet hours, never the cap. Importantly, the reference uses zero to mean unlimited; these guards cover supported delivery helpers, not arbitrary agent tools. [Dispatcher](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/scripts/companion_dispatch.py), [outreach](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/scripts/companion_outreach.py)
- **Hermes and Telegram:** Hermes owns conversations and agent/tool execution; the companion layer supplies profile/vault files, context plugins, schedules and boundaries. Telegram is a configured Hermes delivery transport, not an independent built-in Rust channel. Source includes runtime/SSE bridges and compatibility checks. Reading, media and other tools remain capabilities with their own dependencies and provider costs. [Architecture](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/docs/ARCHITECTURE.md), [Hermes bridge](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/app/hermes_stream.py)
- **Bounded background work:** maintenance can run without an agent. Autonomy fingerprints skip unchanged inputs, but include a six-hour time bucket, so even an uneventful day can trigger four autonomy runs. The marketing phrase about never running when nothing changes needs that qualification. Routine counts differ between high-level README and more detailed current docs; do not promise a fixed count. [Preread/fingerprint](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/scripts/companion_preread.py), [schedule installer](https://github.com/tamanitomo/tamanitomo/blob/f536408bec0b99eef8487e55b78ee40e91a22463/kit/cli/scaffold.py)

## Native implementation order

Status here describes the inspected native source, not a claim of complete runtime acceptance. Existing `src/data.rs` stores per-character persona, scene, provider and voice overrides, plus a rolling history capped at 200 turns/2 MiB. That history is explicitly not long-term semantic memory. Animator and other concurrent work should be assessed in their own implementation receipts.

| Priority | Capability | Native status and proposed scope |
| --- | --- | --- |
| P0 | Avatar, chat, voice, character presets | Existing base source; stabilize import, rendering, animation, voice interruption and saved settings first. |
| P1 | Inspectable durable memory | Explicit per-character notes, pin/edit/delete, opt-in lexical retrieval and bounded background JSON storage implemented. Richer evidence ledger remains recommended. Per-character fact ledger with source turn IDs, evidence excerpts, explicit edits/corrections/delete, expiry, and bounded retrieval. Keep imagined life and user facts separate. |
| P1 | V/A/D and behavior | Recommended integration of the recovered design: typed appraisal, persistent bounded state, temperament/recovery, deterministic expression/voice compiler and readable receipts. Avoid double-counting appraisal plus reply metadata. |
| P1 | Routine/presence | Initial local routine implemented: off-default per-character weekly anchors, current/next fictional activity and system-local clock in the Scene panel. Deterministic weekly rollover, duplicate/invalid anchor rejection, bounded entries/labels. A separate off-default option shares bounded imagined current/next activity data with ordinary focused and group replies, without saving it as history. No user-presence inference, animation trigger, extra model calls, custom timezone or background scheduler. |
| P1 | Quiet hours and budgets | Recommended prerequisite for proactive behavior. Explicit enabled switch; zero means disabled in our UI, with unlimited a separate deliberate option. Durable dedupe, expiry, daily count and minimum spacing. Default strict quiet hours. |
| P2 | Reflection and journals | Recommended opt-in. One bounded reflection after a changed day, retaining source references; no reflection loop on idle frames. Journal suggestions cannot silently overwrite user facts or persona. |
| P2 | Proactive conversation | Recommended after the local outbox exists. Start with in-app notices; short event-triggered drafts, quiet-hour gate, expiry, cancellation and visible reason. No guilt-inducing relationship behavior by default. |
| P3 | Telegram and tools | Deferred integration. Separate adapters with explicit account/channel scope, allowlisted operations and the same outbox gate. Optional Hermes bridge, not a mandatory replacement for the Rust runtime. Read-only tools first; sending requires configured user authorization. |
| P3 | Media and broader life simulation | Deferred. Photo generation, wardrobe stories, ambient sensors and richer fictional relationships are optional modules with independent budgets and controls. |
| Later | Fly connectome and XR/VR | Experimental/deferred. Neither is a prerequisite for memory, daily routines or a useful companion. |

## Suggested initial resource envelope

These are proposed defaults, not measured performance or Tamanitomo defaults:

- **Rendering:** animate locally at the chosen frame rate; no network request, model evaluation, disk scan or journal work per render frame. UI messages cross to bounded background workers.
- **Scheduling:** one local scheduler, nearest-deadline wakeups, no overlapping same-profile jobs. Check local presence/outbox at most once per minute when needed; idle state changes are deterministic. Pause heavy work when suspended or on battery if configured. Resume once, skipping expired jobs rather than replaying a backlog.
- **LLM autonomy:** disabled initially. When enabled, maximum four background calls/day across a character, minimum 60 minutes between calls, one request in flight, 20-second timeout, and no automatic paid fallback. Meaningful changed-input fingerprints avoid repeat work. Show a global daily cap as well as per-character limits.
- **Reflection:** at most one/day with new conversation; suggested 8,000 input and 1,000 output tokens. Count it inside the background-call allowance. Skip rather than retry repeatedly when unavailable.
- **Memory:** begin with deterministic lookup over a bounded active set; at most eight excerpts / 4,000 characters inserted into a turn. Keep originals on disk with retention controls. Embeddings are optional later, not a continuous background requirement.
- **Outreach:** off by default; when enabled, one proactive notice/day, at least four hours apart if the user raises the cap. Dispatch one eligible entry per wake; expire old drafts. Unknown transport outcomes require inspection rather than automatic resend.
- **Observability:** display last/next job, why skipped, provider and token usage, queue length, current budget, and memory citations. An unavailable model should appear unavailable, not silently become simulated provider success.

Acceptance should exercise restart, suspend/resume, quiet hours across midnight/DST, duplicate scheduling, unknown delivery, profile isolation and memory corrections. Source presence and upstream tests are evidence of implementation work; they do not establish live parity on this host.
